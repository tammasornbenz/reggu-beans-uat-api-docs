1. Scope and system context1. ขอบเขตและบริบทของระบบ

This document describes the HTTP JSON interfaces used between Reggu and BEANS on the User Acceptance Testing (UAT) environment. It is intended for integration engineers, QA, and partner technical review.

เอกสารนี้อธิบายส่วนต่อประสาน HTTP JSON ระหว่าง Reggu กับ BEANS บนสภาพแวดล้อม UAT สำหรับวิศวกรเชื่อมต่อ ฝ่าย QA และการทบทวนทางเทคนิคของพาร์ทเนอร์

2. Security and authentication2. ความมั่นคงปลอดภัยและการยืนยันตัวตน

Authentication is performed via custom request headers. This differs from RFC 7235 Authorization and should be treated as an integration-specific convention for UAT.

การยืนยันตัวตนใช้ request header แบบกำหนดเอง ซึ่งต่างจากมาตรฐาน RFC 7235 Authorization และถือเป็นข้อตกลงเฉพาะของการเชื่อมต่อบน UAT

HeaderApplies toใช้กับRequirementข้อกำหนด
keyGateway and HQMandatory. Invalid value returns HTTP 401.จำเป็น ถ้าผิดจะได้ HTTP 401
projectnameHQ APIMandatory for HQ. Example value: TRUNK.จำเป็นสำหรับ HQ ตัวอย่างค่า: TRUNK

3. Status and business-code model3. แบบจำลองสถานะและรหัสธุรกิจ

Several operations return HTTP 200 while conveying outcome through a business code field. Authentication and some validation failures use standard HTTP 4xx statuses.

หลายการทำงานคืน HTTP 200 และสื่อผลลัพธ์ผ่านฟิลด์ business code ส่วนความล้มเหลวด้านการยืนยันตัวตนและการตรวจสอบบางกรณีใช้ HTTP 4xx ตามมาตรฐาน
